## Migration plan

Next free number is `061`. `059` and `060` are already written and not applied (`rebrand-ruzz`); hosted has 001 to 058 applied, so Phase 3 would apply 059, 060 and 061 together.

Hosted and local definitions match: for the 14 functions and 2 triggers the md5 of `pg_get_functiondef` / `pg_get_triggerdef` on hosted equals the one on a fully migrated local database. The new definitions are therefore generated from `pg_get_functiondef` with only the matched text replaced.

| Object | Change |
|---|---|
| `enforce_billing_gate`, `enforce_org_club_limit` | message text; already in `059` |
| `subscription_plans.name` | already in `060` |
| `username_reserved(text)` | `'club27'` stays, `'ruzz'` added |
| 11 functions with `club27.*` | `club27.` to `ruzz.` (Phase 2 part of `061`) |
| 2 triggers | recreated with `ruzz.order_request`, `ruzz.payment_request` (Phase 2) |
| `superadmins.email` | `UPDATE public.superadmins SET email = replace(email, 'club27.test', 'ruzz.test') WHERE email ILIKE '%club27.test'` |

All statements are idempotent: `CREATE OR REPLACE`, `DROP TRIGGER IF EXISTS`, and `UPDATE ... WHERE col ILIKE`. The `UPDATE` lists only the columns above.
